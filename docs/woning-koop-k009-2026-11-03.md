## What changed

line, quantity = floors, full price, no discount. Rented packages are unchanged (monthly N0008 / E001 at
`pkg_qty` x floors).

## Deviation from the brief: no `all_products` lookup for the Koop Woning products

The brief said to call `zv-woning-variants` a second time with the koop handles. That would add two unique
`all_products` handles to pages that are already at Shopify's limit of 20 per page
(`docs/uitbreidingen-koop-only-nami-2026-10-27.md` §7; the header's `zv-hidden-cart-lines` runs on every
page, and /cart hit the same cap on 2026-11-02, see `docs/addon-rider-fixes-2026-10-30.md`). A lookup past
the limit resolves **blank**, silently. So nothing resolves them by handle any more:

- Server side (Liquid): `snippets/zv-woning-koop-lines.liquid` reads the id of a Koop Woning line **off the
  cart** (product handle and `item.sku` equal the config's). That is all /cart, Overzicht and the header
  count need (hide it from the count, label it, group it, gate it).
- Scripts: recognise it by `it.handle` in Cart AJAX data. To **add** one they fetch
  `/products/<handle>.js` and require the first variant's SKU to be the config's
  (`woningKoopVariantId()` on Oplossingen, `resolveKoopWoningIds()` in the guard).
- `check_pricing.py` fails if any theme file renders `zv-woning-variants` with the koop handles.

## Overzicht gate

A bought package's floors used to feed `woning_floor_log` (the monthly gate). They now feed
`woning_koop_floor_log`; per Koop Woning product the gate (`cart_woning_bad`, same contact message) requires
quantity == floors over that platform's bought packages, one line, no discount, unit ==
`zv_woning_koop_unit_cents`. Floors with no line also block (the guard adds it; a cart it can't add to must
not check out without it). The brief didn't list Overzicht; without this change every bought package with
a Woning choice would have been blocked, because the monthly gate would have expected the line the guard
no longer creates.

## Not done / open

- **The Koop Woning products must stay out of the "Eerste 3 maanden" discount** (Admin, never from here).
  If they are added, Overzicht blocks every bought package with a Woning choice (by design).
- How Odoo bills a bought Woning (one-time EUR 100 per floor, no monthly figure) is not decided here: it
  is now a real Shopify line, unlike 2026-10-24 to 2026-10-27, so it can be keyed off.
- The Meer-informatie modal's Woning options keep "/mnd": the modal only adds Huren. If it gets a Kopen
  mode, give those options the same swap.
- A Koop Woning line is added only if `/products/<handle>.js` answers with the config SKU. If it doesn't
  (product unpublished), a bought package keeps the Woning property, no line, and Overzicht blocks
  checkout until the line exists. That is stricter than the Huren side (property-only fallback), on purpose:
  a missing line is under-billing, not over-billing.
- Cart permalinks and direct `/checkout` skip all of this, as for every other line (CLAUDE.md known limitation).
